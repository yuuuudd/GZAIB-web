# 共创项目闭环设计

## 目标

把共创广场从静态示例改为真实项目入口：卡片打开详情弹窗，成员可向发起人发送连接申请；登录成员可以新建、编辑、下架和重新公开自己的项目。

## 数据

新增 `co_create_projects` 表。项目归属于 `users.id`，包含标题、类型、范围、招募状态、摘要、详细介绍、希望解决的问题、招募角色、投入说明、截止时间、经验级别、发布状态以及创建/更新时间。发布状态只有 `published` 与 `archived`；下架保留数据。

现有三条示例数据迁移到数据库，并在生产环境绑定邮箱 `2074712958@qq.com` 对应的用户。公开广场只读取 `published` 项目；“我的共创”读取当前用户的全部项目。

## 页面与交互

- 共创广场的“发起共创”进入 `/me/co-creates/new`，“我的共创”进入 `/me/co-creates`。
- 点击项目卡片打开无页面跳转的详情弹窗。
- 弹窗展示标题、分类、范围、状态、项目介绍、问题、角色、投入、截止时间、发起人和更新时间。
- 非发起人看到“申请加入”；发起人看到“管理项目”。
- “我的共创”提供新建、编辑、下架与重新公开操作。创建后立即公开。

## 连接闭环

“申请加入”复用现有连接请求 API 和审核入口。请求主题自动使用项目名称，申请人填写一句合作说明。发起人在现有“新的朋友/连接申请”页面同意后，双方解锁联系方式。不新增项目申请表、项目成员表或第二套审批系统。

未登录用户先去登录，并携带返回共创广场的路径；自己的项目、已有待处理请求、已经连接和不可用账号继续使用现有连接状态。

## 权限与校验

公开读取只返回已发布项目。新建、编辑、下架和恢复都要求有效登录；更新时同时按项目 ID 与当前用户 ID 限定，任何客户端传入的 owner 值都被忽略。标题、摘要、详情、问题、角色和投入做非空及长度校验，截止时间可选。

## 测试

覆盖项目输入校验、公开/个人查询、归属校验、新建、编辑、下架和恢复；覆盖卡片打开详情、自己的项目显示管理入口、他人项目进入连接申请且带项目主题；最后运行单元测试、lint、生产构建和浏览器冒烟验证。
