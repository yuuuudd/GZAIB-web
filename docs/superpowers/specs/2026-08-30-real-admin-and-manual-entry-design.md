# 真实管理员与手动录入设计

- 项目：广州 AI 共创社 · 共建地图
- 日期：2026-08-30
- 状态：待用户审阅

## 目标

将当前仅供演示的 `demo-admin` 后台替换为可上线使用的管理员模式。唯一管理员是通过 ChatGPT 登录识别出的 `jl5319604@gmail.com`。管理员可进入后台、录入学校、手动录入成员资料，并继续使用既有审核、成员管理和贡献确认能力。

`2074712958@qq.com` 是联系邮箱，不拥有管理员权限。

## 身份与权限

访问 `/admin` 时，系统从 Sites 提供的 ChatGPT 身份头读取已登录用户；没有登录时跳转至 ChatGPT 登录页。登录后的邮箱必须命中服务端环境变量 `ADMIN_EMAILS`，否则返回无权限页面，且所有 `/api/admin/*` 写入接口同样拒绝该请求。

本地开发时保留现有 `DEMO_MODE` 和 `demo-admin`，以便演示和回归测试；生产环境不显示演示身份切换器，也不接受演示会话作为管理员身份。

## 后台界面

在公开地图页增加低干扰的“管理员入口”，未授权访问会进入登录或无权限状态。后台侧栏新增“手动录入成员”。

手动录入成员页包含：昵称、真实姓名（仅管理员可见）、学校/校区、一句话介绍、技能方向、参与角色；专业、年级、当前关注、可提供内容、希望认识的人和作品链接为可选项。管理员提交后生成可编辑的成员资料及审计记录。资料默认不公开，管理员在提交时明确选择“保存为草稿”或“确认发布到地图”；发布要求学校坐标已确认且地图必需字段采用公开默认范围。

现有“学校坐标”页继续作为学校资料入口。未配置高德 Web 服务 Key 时，管理员仍可手工填写坐标候选，确认后才允许该学校被用于地图发布。

## 数据与流程

手动录入会创建一个由管理员管理的成员账户占位记录、成员资料和一条审计记录。该记录没有可登录凭证，不能冒充本人发送连接请求；后续真实成员申请并完成身份确认后，再走合并流程（本期不实现合并）。

所有管理员操作沿用现有审计日志：录入成员、保存草稿、发布、隐藏和修改学校均记录操作者、对象、动作和时间。公开目录继续只读取已发布、有效且学校坐标已确认的资料。

## 失败与安全边界

- 未登录：跳转至 ChatGPT 登录。
- 已登录但邮箱不在白名单：显示无权限，API 返回 403。
- 缺少 `ADMIN_EMAILS`：生产环境默认拒绝全部管理员访问。
- 字段校验失败、学校不存在或学校坐标未确认：不写入公开资料，显示明确提示。
- 管理员手动录入资料不包含登录邮箱、联系方式或个人实时位置。

## 验证

测试覆盖：白名单登录、未授权 API 拒绝、生产环境拒绝演示管理员、手动录入字段校验、草稿不公开、已确认学校的发布、未确认学校阻止发布，以及每次写入产生审计记录。完成后运行全量测试、构建和私有发布。
