# 广东高校共建者地图 Demo

这是广州 AI 共创社的本地演示版：在广东地图上浏览经审核的学校与成员；点击成员可查看公开资料，并通过「想认识 TA」直接发起、接受或拒绝连接请求。双方接受后才可读取彼此**当前**的联系名片。地图展示的是学校/校区聚合坐标，不采集个人实时位置。

> 演示模式使用固定虚构身份，绝不能用于公开发布、收集真实个人资料或正式运营。

## 本地启动

需要 Node.js `>=22.13.0`。安装依赖后，复制 `.env.example` 为仅存在于本机的 `.env`，填入本地演示所需的值。

```powershell
npm.cmd install
npx.cmd wrangler d1 execute site-creator-d1 --local --file=drizzle/0000_builder_map_core.sql --persist-to=.wrangler/state/v3
npx.cmd wrangler d1 execute site-creator-d1 --local --file=drizzle/0001_member_connections.sql --persist-to=.wrangler/state/v3
npm.cmd run dev
```

打开本地地址后，选择「以运营员体验」并前往 `/admin` 点击「初始化 Demo 数据」。该操作可重复执行，不会重复创建固定数据。随后可在身份切换器中使用：

- `demo-admin`：审核申请、确认学校坐标与贡献、处理举报和成员状态。
- `demo-member`：共建者 A，可保存联系名片并给共建者 B 发起请求。
- `demo-peer`：共建者 B，可接受/拒绝请求、拉黑或举报共建者 A。

完整体验顺序：A 保存名片 → A 给 B 发起连接 → B 在「我的连接」接受 → 双方在已连接页看到实时更新的名片 → B 拉黑 → 双方立即不能读取名片或再发起连接。

## 本地环境变量

不要提交 `.env`、实际 Key、真实邮箱或成员数据。以下表格是目前代码的本地配置契约；留空的可选项会降级或关闭相应能力。

| 变量 | 是否必需 | 本地 Demo 用途 |
| --- | --- | --- |
| `DEMO_MODE=true` | 是 | 只允许固定的三种虚构身份和 Demo 管理入口。 |
| `DEMO_SESSION_SECRET` | 是 | 至少 32 个字符；签名 8 小时 HttpOnly 演示会话。 |
| `CONTACT_ENCRYPTION_KEY` | 连接名片时必需 | 恰好 32 字节的 base64；用于 AES-GCM 加密联系名片。 |
| `APP_ORIGIN` | 建议 | 例如 `http://localhost:3000`；用于邮件中的站内链接和安全的公开元数据。 |
| `RESEND_API_KEY`、`RESEND_FROM` | 可选 | 两项同时有效才尝试邮件提醒；没有配置时只有站内通知，不会真的发信。 |
| `NEXT_PUBLIC_AMAP_JS_KEY` | 可选 | 高德 Web JS Key；未配置时仍保留可浏览的学校列表。 |
| `AMAP_SECURITY_JS_CODE`、`AMAP_WEB_SERVICE_KEY` | 可选 | 服务端高德安全代理/地理编码配置，不能暴露到浏览器。 |

`ADMIN_EMAILS`、生产会话签名密钥、真实认证回调和公众号凭据并未接入这个 Demo；不要为本地 Demo 虚构或提交这些生产配置。

## 数据、隐私与安全边界

- D1 绑定名为 `DB`，头像 R2 绑定名为 `AVATARS`；本地迁移必须顺序执行 `0000` 和 `0001`。
- 联系名片在库中只保存 AES-GCM 密文；请求正文、公开地图、搜索结果、普通资料页和通知邮件均不包含联系方式。
- 仅「双方已接受、双方仍为已审核公开活跃成员、且没有任一方向拉黑」时，服务器才解密并返回对方的当前名片。
- 连接每位发送者滚动 24 小时最多 5 条；服务端拒绝客户端伪造的发送者、隐藏目标或直接在正文中留联系方式。
- 拉黑会原子地取消双方待处理请求，并即时撤销已接受关系的名片读取权；取消拉黑不会恢复旧请求。
- 举报仅让举报人查看自己的最小状态；只有固定 Demo 运营员可以处理举报，连接限制等处罚会写入审计记录。
- 自助注销会撤销会话、隐藏资料、删除名片、取消待处理连接并保留最小化的审计/举报解释记录。

## 运营演练

1. 运营员初始化 Demo 数据，核对学校坐标后再审核申请；通过并发布的资料才会出现在地图和通讯录。
2. 学校变更先作为提议保存，确认坐标后才影响公开展示；不要手工写库修改成员资料。
3. 在 `/admin/reports` 选择合适的处理结果。`suspend_connections` 只禁止该成员再发起连接，不会删除既有审计证据。
4. 邮件发送失败不会回滚连接/审核状态：检查通知记录的 `delivery_status`，修复邮件配置后用受控流程处理后续提醒；不要把联系名片写进邮件正文。
5. 更换 `CONTACT_ENCRYPTION_KEY` 时先维护旧/新密钥的安全轮换适配，再逐条解密并以新密钥重加密；在全部记录完成迁移前不能直接替换旧 key。这个 Demo 当前只支持单密钥，真实轮换应另行实施和演练。
